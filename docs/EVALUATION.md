## 指标具体是什么意思

- **Hit@K**：标准证据中至少一条进入前 K 个原始检索结果，该题记为命中。
- **MRR@5**：在前 5 条中找到的第一条标准证据排名为 r，该题得 1/r；没找到记 0；对 27 道题取平均。
- 同节相邻上下文补充不计入这些指标。
- 3 道资料外问题单独记录，不纳入上述分母，也没有被当作拒答成功。

这些指标回答的是“证据有没有检索到、排得靠不靠前”。它们不评价模型回答是否正确、完整或忠于原文。

## 已知失败值得展示

| 问题 | BM25 的 Top-5 | 向量的 Top-5 | 能看出什么 |
|---|---|---|---|
| Q15：LlamaIndex Evaluation、Ragas、Phoenix 该怎么选？ | 未命中标准证据 | 命中 | 关键词匹配可能找到同主题章节，却未覆盖指定证据；需要检查具体片段与题目标注 |
| Q05：Function Calling 是什么，它在 RAG 里解决什么问题？ | 命中 | 未命中 | 向量相近不保证命中该题的标准证据；不能只看总体 Top-1 提升 |
| Q22：块切得太碎，匹配到词却上下文不连贯，一般如何缓解？ | 命中 | 未命中 | 描述式问题也可能被向量方法排到相邻主题，需要逐题核查排序 |

表中“未命中”只表示按照当前标注与判据，Top-5 中没有标准证据；不是对模型回答做了判错。可能原因是待验证的解释，不能只凭排序结果认定机制原因。

## 关于拒答和生成质量

离线对照未为 BM25 与向量方法建立可比较的拒答阈值，3 道资料外问题仍返回了检索结果。这里仅记录观察，不报告“拒答通过率”。BM25 分数与向量相似度也不能当作同一把标尺。

生成层已有小批量真实调用与执行方的人工检查记录，其中包括 15 条后续样本。但这 15 条尚未完成独立语义复审，本页不把执行方的检查汇总写成已证明的回答准确率。早期检查记录见 [Git 历史中的生成验证记录](https://github.com/1980c-L/rag-power-regs/blob/df86a094568e695d11a6deb5e93a49413054ba18/生成验证记录.md)；它属于历史材料，不覆盖后续全部样本。

## 如何复核

只核对已发布的报告、CSV 与清单是否一致，无需下载嵌入模型，也不会重新调用生成模型：

```powershell
python 06_eval_vector.py --corpus rag_learning --verify-published
```

退出码 0 只说明这组产物通过程序的发布一致性检查，不等于重新运行了检索或证明回答质量。

重新跑 BM25，需要先按 [运行指南](QUICKSTART.md) 导入固定版本的资料：

```powershell
python 04_eval.py --corpus rag_learning
```

该命令会写本地评测报告；建议在自己的工作副本中执行并保留原始报告。向量实验还需要额外的 ONNX 推理依赖和本地模型文件，仓库未附带模型与缓存；具体配置入口见 [vector_retriever.py](../vector_retriever.py)。仅安装主运行依赖不能直接重跑向量实验。

当前数据来自小型自建评测集。继续改检索方法时，应保留开发题与新验证题的区别，避免反复围着这 27 道题调参后仍把它们当作独立测试。
