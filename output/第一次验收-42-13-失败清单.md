# 第一次 EXE 验收 42 PASS / 13 FAIL 的失败清单（摘录）

> 来源：2026-09-22 当次终端输出。**原始日志文件已被第二次运行的同路径重定向覆盖**，
> 本文件是事后逐条整理，属于摘录而**非原始日志**（见 54 号交付说明 §3b 的披露）。
>
> 环境事实：`release\RAG问答助手-0.5.1\RAG问答助手.exe`（PID 18808，20:54:37 启动）当时仍在运行，
> 且 `LISTENING` 于 `127.0.0.1:5273` 与 `127.0.0.1:5280` —— 正是验收所用的两个端口。
> 该实例随后由 `--stop` **自行退出**（未强杀任何进程），同一命令重跑得 **PASS 55 / FAIL 0**。

## 13 条失败判据（原样摘录）

1. EXE·meta：data_source=api 且 Key 未配置（验收环境确实没有 Key）
2. EXE·无 Key：生成请求落到 no_api_key，没有回答与引用（零模型请求）
3. EXE·批量：每条的命中（含原文）与源码环境逐字段一致
4. EXE·导出：CSV 成功（200/BOM/表头 15 列含 hit_* 命中证据列/行数=题目数+1）
5. EXE·导出：DOCX 里真的有命中原文（报告能自证「命中了什么」）
6. EXE·用户库：粘贴导入成功（来源数 1）
7. EXE·停止：强制结束验收实例后两个端口都已释放（不留监听）
8. EXE·重启：用户资料仍在（数据落在 EXE 同级，重启不丢）
9. EXE·重启：旧批量任务不再可见（第一版不续跑、也不自动重放）
10. EXE·停止：--stop 正常退出（rc=0）
11. EXE·停止：两个端口都已释放
12. EXE·只读位置：失败后没有留下监听端口
13. EXE·只读位置（对照）：可以正常停止且端口释放

## 为什么这 13 条指向同一个原因：请求打到了旧实例

- 「批量命中不含原文」「CSV 不是 15 列」「DOCX 无命中原文」三条都是**旧代码特征**
  （旧版既不保存 `text`，CSV 也只有 10 列）；
- 「用户库来源数=2」：旧实例的用户资料目录在 20:54 之前已经导入过一次来源；
- 「端口未释放」/「`--stop` 没有可用的启动记录」：验收实例与旧实例的运行记录互不一致；
- 与此同时，「页面是 api 版前端」「内置学习库统计一致」「检索命中一致」「身份防护」等
  **与源码无关**的判据仍然 PASS —— 说明服务确实在响应，只是响应者不是本次解压出来的 0.5.2。

## 复现与恢复步骤

```powershell
& '.\release\RAG问答助手-0.5.1\RAG问答助手.exe' --stop   # 让旧实例自行退出（不杀无关进程）
python -X utf8 verify_exe_package.py --zip 'release\RAG问答助手-0.5.2.zip' --out 'output\exe-evidence-0.5.2'
# → 便携 EXE 验收：PASS 55 / FAIL 0
```
