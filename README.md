# RAG 问答助手（电力示例库 + RAG 技术学习库）

> 一个"提问 → 检索资料 → 标注引用出处"的检索增强生成（RAG）应用。
> 用途：作为"大模型应用开发"方向的实习求职作品。
> 作者画像：二本电气大三，目标是证明"能用 AI 完成工程交付 + 能讲清原理"。

## 一句话说清它是什么

把一批资料切碎、建索引；你问一个问题，它先从资料里检索出最相关的段落，再把这些段落喂给大模型生成答案，并要求模型在答案里标注出处。

**设计目标：让大模型"引用出处、有据可依"** —— 这是 RAG 相比裸聊大模型的思路。本轮新增的重点是：**资料是真的、来源可追溯、指标可重复、失败案例如实保留**。

## 快速开始

```powershell
# 0. 安装依赖（jieba 用于中文分词，缺失会自动退回字符 bigram）
pip install -r requirements.txt

# 1.（首次）导入真实语料：从 Datawhale《All-in-RAG》本地克隆生成语料 + 来源清单
python tools/import_rag_corpus.py --repo "<all-in-rag 本地克隆路径>"

# 2. 建索引（两个库一起）
python 01_prepare.py

# 3. 检索（不需要 API key）
python 02_retrieve.py "BM25 打分为什么要做文档长度归一化" --corpus rag_learning --top-k 3

# 4. 离线评测（不需要 API key，不调用模型）
python 04_eval.py

# 5. 端到端问答（需要 DeepSeek API key）
$env:DEEPSEEK_API_KEY = "sk-xxxx"
python 03_qa.py "RAG 评估三元组包含哪三个维度" --corpus rag_learning

# 6. 启动网页工作台
streamlit run app.py

# 7. 跑验收（全程离线；54 项 PASS + 1 项 NOT VALIDATED）
python verify_flows.py

# 8. 语料两级校验
python tools/import_rag_corpus.py --self-check      # 交付文档 vs 交付 manifest
python tools/import_rag_corpus.py --upstream-check  # 在钉扎 commit 上重建上游并逐字节比对
```

### 网页工作台说明（app.py）

- **知识库选择**：电力示例库 / RAG 技术学习库，两个库完全隔离
- **两种模式**：仅检索（离线可用）/ 检索并生成（需 API key，读服务端环境变量）
- **语料信息**：来源数、chunk 数、字符数、上游 commit、切分参数、分词器、语料指纹
- **命中片段可追溯**：展示来源标题、章节标题层级、来源组织与原文链接（钉扎到具体 commit）
- **Top-K 可调**（1–5）
- **检索命中与同节补充分开呈现**：主区只展示真实 BM25 Top-K；生成时补入的同节相邻上下文
  以独立标题和逐条折叠片段展示，标注"**不计入检索命中，也不计入 Hit@K / MRR**"
- **引用对照按首次出现顺序去重**：同一来源在回答里被引多次，对照区只展示一次，
  并标注该来源是「检索命中」还是「同节补充」；模型编造的 id 与 markdown 链接文字不会混进来
  （**链接文字恰好等于真实 chunk id 时同样不算引用**，判据是"方括号 id 后面不能紧接 `(`"，S12c/S12f）；
  `[来源：<id>]` 这类带前缀写法会被正确识别（2026-09-20 按 21 号真实样本窄修，S12g）
- **四种路径都兜住**：成功 / 零结果（不调模型）/ 无 key（只展示检索）/ 生成失败（保留检索结果）
- **缓存**：按"语料指纹 + 知识库"失效，界面重绘不重复调用模型
- 诚实标注：把 BM25 得分标为"检索得分（非置信度）"，不展示"回答准确率"，
  并在回答区标注"生成层尚未完成正式验证"

> 可选：用 `streamlit run app.py --server.port 8501` 指定端口。本地预览地址为 `http://localhost:8501`。

## 第三版独立前端（frontend_v3）：两种数据源

第三版是一个独立前端（React + TS + Vite，固定 `127.0.0.1:5273`）。数据源由**构建期环境变量**选择，
配置只在一处（`frontend_v3/src/services/config.ts`）：`VITE_DATA_SOURCE` 与 `VITE_API_BASE`。

**A. 接真实资料（api 模式）** —— 页面通过本机薄接口读取真实学习库并实时检索：

```powershell
# 终端 A：本机薄接口（只绑 127.0.0.1:5280）
python api_v3.py

# 终端 B：构建并预览前端
cd frontend_v3
npm install
$env:VITE_DATA_SOURCE = "api"
$env:VITE_API_BASE = "http://127.0.0.1:5280"
npm run build
npm run preview            # http://127.0.0.1:5273
```

**B. 第一阶段示例数据（mock 模式）** —— 不设环境变量直接构建，行为与第一阶段验收时一致：

```powershell
cd frontend_v3
Remove-Item Env:VITE_DATA_SOURCE, Env:VITE_API_BASE -ErrorAction SilentlyContinue
npm run build
npm run preview
```

**停止**：两个窗口各按 `Ctrl+C`。若预览进程残留占着 5273，用 `taskkill /F /T /PID <pid>` 结束整棵进程树
（Windows 下只关外壳会留下孤儿 node）。

**边界（必须一起说清）**：`api_v3.py` 只绑定 `127.0.0.1`，**没有鉴权、没有 TLS，不要部署到公网**；
CORS 只允许本机 5273 来源。API Key 只留在服务端进程里，接口只返回"有没有配 Key"的布尔值，不回显内容。
**默认不发任何真实模型请求**：只有 `mode=generate` 且服务端检测到 Key 时才会走到生成层，
目标地址由服务端 `config.py` 决定（联调时可用 `--llm-base-url` 指向本机桩）。

**验收**（两套计数分开报告，互不覆盖）：

```powershell

python verify_frontend_v3.py --backend mock    # 页面：第一阶段回归
python verify_frontend_v3.py --backend api     # 页面：真实资料联调
```

## 两个知识库

| 知识库 | 语料 | 规模 | 切分方式 | chunk id 形态 |
|---|---|---|---|---|
| `power_demo` 电力示例库 | 《电力安全通用要点》示例语料 | 1 份 / 12 chunk / 1.1 KB | 按空行分段，超 400 字符再切 | `示例语料-…#P5` |
| `rag_learning` RAG 技术学习库 | Datawhale《All-in-RAG》第一批 10 篇 | 10 份 / 471 chunk / 71.1 KB | **标题感知**：先按 Markdown 标题分节，再按段落切，超 400 字符兜底 | `air-eval-tools#s12p2` |

设计要点：

- **隔离**：库之间不共享索引；chunk id 命名空间不重叠；评测集与报告也分库保存。
- **稳定 id**：`{source_id}#s{节号}p{段号}` 只由"文档内容 + 按 source_id 排序"决定，与文件遍历顺序无关，重复运行结果一致。
- **检索文本 vs 展示文本**：检索时把标题层级拼进 `search_text`（便于命中章节名），界面与评测只展示正文 `text`，避免重复堆标题。
- **列表与代码块边界**：相邻列表项合并为一个语义单元（不被空行切成碎片）；代码块即使含空行也不切开。
- **评测集与语料物理隔离**：`eval/` 与 `data/rag_learning/documents/` 分开，标准答案不会进入检索语料。
- **生成上下文按需补全同节相邻片段**：BM25 按 chunk 打分，命中常落在章节的**前言/总结**上，
  而真正枚举答案的相邻片段可能整段掉在 Top-K 之外（实测见「已知边界」第 9 条）。
  因此生成时会在**同 `source_id` + 同 `section`** 内补入相邻片段（左右各 2 个、总预算 4000 字符），
  补进来的片段带 `origin="neighbor"` 标记，**不参与检索命中、不参与 Hit@K / MRR**。

## 技术原理（面试必问，逐层讲清）

| 层 | 做了什么 | 关键点 / 证据状态 |
|---|---|---|
| **切分** | Markdown 标题分节 → 段落切分 → 超 400 字符按字数兜底；每段带来源、标题层级、原文链接 | 出处由切分阶段赋予；列表与代码块边界被保留 |
| **检索** | jieba 分词 → BM25（k1=1.5, b=0.75）打分 → 取 Top-K | ✅ 真实资料上可离线复现（Hit@1 70.37%，MRR 0.8111） |
| **上下文组装** | 命中片段 + 同节相邻片段（各带 `origin` 标记）拼成【资料】 | ✅ 离线可验证（S11）；补充片段不参与命中与指标 |
| **生成** | prompt 约束"只依据资料、标引用、缺了就说没有"，并要求区分同节补充片段 | ⚠️ **未完成正式验证**：当前 prompt 下 8 例用户侧样本，宽泛问法存在拒答问题 |
| **评测** | 30 题，判据是"标准证据 chunk"（`chunk_id` / `section_exact` / `section_prefix`），输出 Hit@K / MRR | ✅ 一条命令重生成；失败题清单如实保留 |

**BM25 一句话**：一个词在问题里出现、在全库越稀有（比如"重排序"）、在当前段出现越频繁，
这段得分越高；同时用文档长度归一化，避免长文档仅因更长而占优。

**BM25 三个参数的作用**：`k1` 控制词频饱和（出现再多也不会无限加分）、
`b` 控制长度归一化强度（b=0 完全不归一化，b=1 完全归一化）、IDF 反映词的稀有度。

6. **`Hit@K` 是"标准证据章节是否被召回"，不等于回答质量**：它衡量检索，

   样本量与判据都还不构成独立复审意义上的正式验收，因此本条状态**仍是「未完成正式验证」**。
8. **判据口径变化会让指标不可直接比较**：本轮把标准证据从"子串匹配"改为显式判据后，
   Hit@1 由 66.67% 变为 70.37% —— 其中既**去掉**了 2 处误判（Q05、Q12），

   `实验说明-真实RAG学习库基线.md` 第四节。
9. **`Hit@K` 是"节级"判据，会"指标命中但答案不可用"**（用户实测发现的真问题）：
   问「RAG 评估三元组包含哪三个维度」时，Top-3 取回的是同章节的**前言**与**总结**
   （`#s2p1`、`#s2p6`）加一节说明（`#s1p4`），而真正枚举三项的 `#s2p2`–`#s2p4`
   **全在 Top-3 之外**；模型于是诚实回答"资料未具体列出三个维度"。
   按现有判据 Q04 仍算**命中**（命中节正确），但产品回答并不好 ——
   说明**指标衡量的是"找对章节"，不等于"拿到能回答的片段"**。
   已用生成阶段的同节相邻补全缓解（`origin="neighbor"`，不计入命中），
   但**指标本身没有反映这一点**，对外表述时必须同时说明。
10. **回答长度没有规则约束，可能偏长**（2026-09-23 核实，用户已确认写入）：
   提示词里**没有长度或结构契约**，`generate_answer()` 也没有 `max_tokens`；
   19 号那句"资料给了几条就列几条"只针对**评价口径／维度类**问题，不是通用长度规则。
   对 15 例真实回答逐条人工核对后，**可删短的约 7 例**（每例 80–260 字），
   典型形态是"**答完问题后追加一段问题没直接询问的补充**"。

   所以**没有为此改提示词**：字数与条数上限**没有实验依据**，压小了可能漏掉步骤、限定条件或引用。
   → 进化（需先定判据与样本）：页面提供"简短／标准"长度选项，把决定权交给用户，而不是让模型猜。

## 局限与进化路径（这是加分项，不是缺点）

1. **现在是关键词检索（BM25），不是语义检索。** 实测同义改写题 Hit@1 只有 33%。
   → 进化：加**向量检索**（embedding + 余弦相似度）或**混合检索 + RRF 融合**，用 Hit@K 对比前后差异。
2. **标题和段落切分之后，长段仍按 400 字符兜底；没有 overlap 或句子边界。** 半句话的块可能丢上下文。
   → 候选改进：按句子边界兜底或加 overlap；先用现有题集验证收益再决定是否改动。
3. **评测判据只到"章节级"**，没有句级标注。
   → 进化：标注段落级标准片段，算更严格的段落级召回；引入忠实度/答案相关性评估。
4. **无相关性阈值，拒答全靠 prompt。**
   → 进化：用一批刻意无依据的问题做校准集，观察分数分布后再决定是否设阈值。

> 面试时可以主动讲这四条：说明你不是只会调包，而是理解每一步的局限和下一步怎么走。
